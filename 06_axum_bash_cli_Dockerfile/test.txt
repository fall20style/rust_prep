그건 "도커 안에서 도커를 실행(Docker-in-Docker)"하려는데, 컨테이너 환경이 호스트의 도커 엔진에 접근할 권한이 없어서 생기는 전형적인 문제임.
우분투 로컬에서 직접 실행할 때는 내 계정이 도커 권한을 가지고 있어서 잘 되지만, 컨테이너로 들어가면 그 안은 격리된 세상이라 외부 도커를 부릴 수 없음.
## 1. 해결 방법: Docker Socket 공유 (가장 쉬운 법)
도커를 실행(run)할 때, 호스트의 도커 엔진 통로(docker.sock)를 컨테이너 안으로 연결해주면 됨.

# 실행할 때 -v 옵션으로 소켓을 공유함
docker run --rm -p 8080:8080 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  axum-app

## 2. 왜 이렇게 해야 함?

* 격리: 기본적으로 컨테이너는 호스트에 무슨 프로그램이 깔려 있는지 모름.
* 권한: -v /var/run/docker.sock... 옵션을 주면, 컨테이너 내부의 앱이 "호스트 형님, 도커 좀 대신 돌려주쇼"라고 요청할 수 있는 통로가 생기는 거임.

## 3. Dockerfile 확인 (CLI 도구 포함 여부)
컨테이너 안에서 docker run 명령어를 날리려면, 이미지 안에 도커 클라이언트(CLI)가 설치되어 있어야 함.
만약 docker: not found 에러가 난다면 Dockerfile에 아래 내용을 추가해서 빌드해야 함. (Debian 기준)

# 실행 스테이지에 추가RUN apt-get update && apt-get install -y docker.io && rm -rf /var/lib/apt/lists/*

## 4. 권한 문제 (Permission Denied)
소켓을 연결했는데도 권한 에러가 나면, 컨테이너를 root 권한으로 실행하거나 소켓 권한을 조정해야 함. 테스트용이라면 --privileged 옵션을 써보는 것도 방법임.

docker run --rm -p 8080:8080 --privileged \
  -v /var/run/docker.sock:/var/run/docker.sock \
  axum-app

## 요약

   1. 컨테이너는 기본적으로 밖의 도커를 못 건드림.
   2. -v /var/run/docker.sock:/var/run/docker.sock 옵션이 핵심임.
   3. 컨테이너 안에 도커 CLI가 깔려 있는지 확인하셈.
